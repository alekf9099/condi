무엇을 해결하나

    

    

      

        
타겟이 코드에 없다

        
URL·API 엔드포인트·셀렉터가 전부 설정에서 옵니다. 다른 사이트를 검증하려면 JSON만 바꾸면 되고, 테스트 코드는 손대지 않습니다.

      

      

        
UI 전에 API로 상태를 만든다

        
브라우저를 띄우기 전에 토큰을 발급하고 데이터를 시딩합니다. 로그인 화면을 매번 클릭해 통과할 필요가 없습니다.

      

      

        
조건부 분기가 선언적

        
API 스텝도 UI 단계도 when 한 줄로 조건부 실행됩니다. if 문을 테스트 코드에 흩뿌리지 않습니다.

      

      

        
셀렉터를 클릭으로 수집

        
페이지에서 요소를 클릭하면 data-testid → id → 최단 CSS 순으로 안정적인 셀렉터를 뽑아 설정에 넣습니다.

      

      

        
실제 세션 그대로

        
확장이라 이미 로그인된 브라우저 세션과 사내망을 그대로 씁니다. 별도 러너를 망 안에 둘 필요가 없습니다.

      

      

        
같은 설정을 CI도 실행

        
uiFlow를 설정에 두었기에 Playwright 러너가 동일한 정의를 그대로 돌립니다. 확장에서 만든 흐름이 곧 회귀 테스트입니다.

      

    

  


  
  

    

      
설정 한 장이 전부

      
이 JSON이 확장과 CI 양쪽의 유일한 입력입니다.

    


    

      
// 어디를 검증할지
"target": { "baseUrl", "apiBaseUrl" },

// 어떤 조건에서 검증할지 — 키는 자유롭게 확장
"conditions": { "userRole": "admin", ... },

// 논리 이름 → 실제 셀렉터
"selectors": { "adminMenu": "[data-testid=admin]" },

// UI 전에 상태 만들기 (when으로 조건부)
"apiSetup": { "steps": [ { "name", "when", "request", "extract" } ] },

// 산출물을 브라우저로
"injection": { "cookies", "localStorage", "extraHTTPHeaders" },

// 무엇을 확인할지
"uiFlow": [ { "action", "target", "value", "when" } ]


      

        
uiFlow 액션

        

          
gotobaseUrl 기준 경로 이동

          
waitForUrlURL에 값이 포함될 때까지 대기

          
click check클릭 · 체크박스 체크

          
fill select입력 · 옵션 선택

          
expectVisible요소가 보여야 함

          
expectHidden요소가 없어야 함

          
expectText텍스트 포함 검증

          
expectValue입력값 일치 검증

          
expectCount요소 개수 검증

        

        
모든 액션은 명시적 대기를 거칩니다. 실패하면 무엇을 기다렸는지가 메시지에 담깁니다.
